## Вопросы

1. `merge` склеивает ветки и может оставить merge-коммит. `rebase` перекладывает коммиты поверх другой ветки, хеши меняются.
2. `--no-ff` всегда делает merge-коммит. Без него при fast-forward ветка на графе пропадает. Так вышло с приветствием. С конфигом merge-коммит остался специально.
3. `rejected (non-fast-forward)` значит, на сервере есть чужие коммиты. Сначала `git pull`, разобрать конфликт, потом push. В `main` через `--force` не затираю.
4. Индекс — то, что попадёт в коммит. `git add` кладёт туда выбранные правки. Без add коммит берёт старую версию из индекса.
5. Незастейдженное убирается `git restore файл`.
6. Что изменено, но не в индексе: `git status` и `git diff`. Уже добавленное — `git diff --cached`.
